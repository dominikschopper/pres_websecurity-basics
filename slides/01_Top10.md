## What is the OWASP Top 10?

- Awareness document for developers & web app security
- Broad consensus on the most critical risks
- 2025 edition – first update since 2021
- Categories, not single bugs
- Not a checklist, not a full test plan

Note:
- awareness doc, not a standard
- update cycle ~4 years
- data: CVEs → CWEs + community survey
- category = group of CWEs
- for verification: ASVS (resources list)

## A01 – Broken Access Control

- Users act outside their intended permissions
- Typical: IDOR (change an ID), force browsing, missing checks on API, tampered JWT/cookie, CORS, CSRF, SSRF
- Fix: **deny by default**, check **server-side**, enforce record ownership

**Cheat Sheets:** Authorization · IDOR Prevention · CSRF Prevention · SSRF Prevention

Note:
- #1 again, every tested app had some form
- client-side check = no check (curl demo)
- one central implementation, reuse
- tests for access control
- Juice Shop: other user's basket, admin section

---

## A02 – Security Misconfiguration

- Unsafe defaults, features nobody needs, defaults left on
- Typical: debug mode, verbose errors, default accounts, open cloud storage, missing security headers
- Fix: hardened, **repeatable** config; minimal platform; same setup across environments

**Cheat Sheets:** HTTP Headers · Content Security Policy · Docker Security · Infrastructure as Code Security

Note:
- config = code (IaC, review)
- remove what you don't use
- check headers live (browser DevTools → Network)
- Juice Shop: exposed metrics endpoint

---

## A03 – Software Supply Chain Failures

- Your dependencies, build tools, CI/CD, registries
- Typical: vulnerable libraries, malicious packages, typosquatting, hijacked maintainer accounts, poisoned pipelines
- Example: **Shai-Hulud** (npm, Sept 2025) – self-replicating worm via stolen tokens
- Fix: lockfiles, audit, fewer deps, vet new packages, protect tokens & CI secrets, 2FA

**Cheat Sheets:** Software Supply Chain Security · NPM Security · Vulnerable Dependency Management · CI/CD Security

Note:
- new in 2025, rank 3
- you install hundreds of packages you never read
- pnpm: lockfile committed, frozen lockfile in CI, pnpm audit
- who can publish? who can push to CI?
- bridge: slopsquatting (Input 3)

---

## A04 – Cryptographic Failures

- Missing or weak crypto for data in transit and at rest
- Typical: HTTP, MD5/SHA-1 for passwords, hard-coded keys, weak randomness, secrets in repos
- Fix: TLS everywhere, strong standard algorithms, **never roll your own**, manage keys properly

**Cheat Sheets:** Cryptographic Storage · Password Storage · Transport Layer Security · Key Management

Note:
- passwords: Argon2id, bcrypt – not "fast hash"
- encryption ≠ hashing ≠ encoding
- secrets in git history stay there
- Juice Shop: "Weird Crypto"

---

## A05 – Injection

- Untrusted data is interpreted as code or command
- Typical: SQL injection, **XSS**, OS command, NoSQL, LDAP
- Fix: **parameterized queries**, context-aware output encoding, allow-list validation

**Cheat Sheets:** Injection Prevention · SQL Injection Prevention · Query Parameterization · XSS Prevention · OS Command Injection Defense

Note:
- data vs. code – keep them apart
- ORM ≠ automatic safety (raw queries)
- frameworks encode by default – until innerHTML / v-html
- Juice Shop: login as admin (SQLi), DOM XSS
- LLM prompt injection = other list

---

## A06 – Insecure Design

- Flaw is in the design – perfect code can't fix it
- Typical: no threat model, missing limits on business flows, unclear trust boundaries, weak recovery flows
- Fix: threat modeling early, secure design patterns, abuse cases next to use cases

**Cheat Sheets:** Secure Product Design · Threat Modeling · Abuse Case

Note:
- can't be found by scanners
- question: "what could go wrong?"
- what if a user does this 1000×? with someone else's ID?
- cheap in design, expensive after release

---

## A07 – Authentication Failures

- Weak proof of identity or weak session handling
- Typical: no brute-force/credential-stuffing protection, weak or default passwords, weak recovery, sessions not invalidated
- Fix: MFA, breached-password checks, rate limiting, solid session management

**Cheat Sheets:** Authentication · Session Management · Multifactor Authentication · Forgot Password

Note:
- don't build your own auth
- recovery flow = back door
- logout must invalidate server-side
- Juice Shop: admin password strength

---

## A08 – Software or Data Integrity Failures

- Code or data is trusted without verifying integrity
- Typical: unsigned updates, insecure deserialization, scripts from untrusted CDNs, unprotected pipelines, tampered tokens
- Fix: verify signatures, Subresource Integrity, never deserialize untrusted data, protect the pipeline

**Cheat Sheets:** Deserialization · Third Party JavaScript Management · CI/CD Security

Note:
- relation to A03: A03 = what you pull in, A08 = trusting it unverified
- JWT: verify signature, fix algorithm
- Juice Shop: forged / unsigned JWT

---

## A09 – Security Logging and Alerting Failures

- Without logs and alerts, attacks stay unnoticed
- Typical: logins & access failures not logged, logs only local, nobody gets alerted, secrets/PII in logs, log injection
- Fix: log security events, central & tamper-resistant, **alert** + response process

**Cheat Sheets:** Logging · Application Logging Vocabulary

Note:
- "alerting" = new in the name
- what do we log in our projects?
- never: passwords, tokens, full card data
- sanitize log input (log injection)

---

## A10 – Mishandling of Exceptional Conditions

- Errors and unusual states handled badly or not at all
- Typical: unhandled exceptions → crash/DoS, **fail open**, stack traces leak internals, inconsistent handling
- Fix: handle at every layer, **fail closed**, generic message to the user / details to the log, test error paths

**Cheat Sheets:** Error Handling · Logging

Note:
- new in 2025, rank 10
- happy path tested, error path not
- fail-open example: auth service down → access granted
- Juice Shop: "Error Handling" challenge

---

## From finding to fix

1. **Spot** the weakness
2. **Name** it – Top 10 category (later: CWE)
3. **Look up** the Cheat Sheet
4. **Fix the root cause** – and add a test

In the challenge hunt: for every finding, tell us **category** and **fix**.

Note:
- check-in format: finding – category – fix
- fundamentals stay the same, AI or not (Input 3)
- Q&A ~5 min
