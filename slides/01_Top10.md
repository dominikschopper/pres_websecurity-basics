## What is the OWASP Top 10?
-----
### What is the OWASP

- [OWASP](https://owasp.org/about) = Open Worldwide Application Security Project
- nonprofit international foundation

-----

## [_THE_ Top 10](https://owasp.org/projects/top-ten)
- Awareness document for developers about the most prevalent threats
- 2025 edition – first update since 2021
- 10 Categories, not single bugs
- Not a checklist, not a full test plan
-----
Nowadays there are other OWASP Top 10 (API, AI, Mobile, ...)

Other OWASP projects [Dependency Check](https://owasp.org/projects/dependency-check), 
[ASVS (Security Verification Standard)](https://owasp.org/projects/asvs) and [many more](https://owasp.org/projects)

Note:
- awareness doc, not a standard
- update cycle ~4 years
- data: CVEs → CWEs + community survey
- category = group of CWEs
- for verification: ASVS (resources list)

## [A01 – Broken Access Control](https://owasp.org/Top10/2025/A01_2025-Broken_Access_Control/)

- Users act outside their intended permissions
- Typical: IDOR (change an ID), force browsing, missing checks on API, tampered JWT/cookie, CORS, CSRF, SSRF
- Fix: **deny by default**, check **server-side**, enforce record ownership

**Cheat Sheets:** [Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) · [IDOR Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Insecure_Direct_Object_Reference_Prevention_Cheat_Sheet.html) · [CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) · [SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

Note:
- #1 again, every tested app had some form
- client-side check = no check (curl demo)
- one central implementation, reuse
- tests for access control
- Juice Shop: other user's basket, admin section

---

## [A02 – Security Misconfiguration](https://owasp.org/Top10/2025/A02_2025-Security_Misconfiguration/)

- Unsafe defaults, features nobody needs, defaults left on
- Typical: debug mode, verbose errors, default accounts, open cloud storage, missing security headers
- Fix: hardened, **repeatable** config; minimal platform; same setup across environments

**Cheat Sheets:** [HTTP Headers](https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html) · [Content Security Policy](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html) · [Docker Security](https://cheatsheetseries.owasp.org/cheatsheets/Docker_Security_Cheat_Sheet.html) · [Infrastructure as Code Security](https://cheatsheetseries.owasp.org/cheatsheets/Infrastructure_as_Code_Security_Cheat_Sheet.html)

Note:
- config = code (IaC, review)
- remove what you don't use
- check headers live (browser DevTools → Network)
- Juice Shop: exposed metrics endpoint

---

## [A03 – Software Supply Chain Failures](https://owasp.org/Top10/2025/A03_2025-Software_Supply_Chain_Failures/)

- Your dependencies, build tools, CI/CD, registries
- Typical: vulnerable libraries, malicious packages, typosquatting, hijacked maintainer accounts, poisoned pipelines
- Example: **Shai-Hulud** (npm, Sept 2025) – self-replicating worm via stolen tokens
- Fix: lockfiles, audit, fewer deps, vet new packages, protect tokens & CI secrets, 2FA

**Cheat Sheets:** [Software Supply Chain Security](https://cheatsheetseries.owasp.org/cheatsheets/Software_Supply_Chain_Security_Cheat_Sheet.html) · [NPM Security](https://cheatsheetseries.owasp.org/cheatsheets/NPM_Security_Cheat_Sheet.html) · [Vulnerable Dependency Management](https://cheatsheetseries.owasp.org/cheatsheets/Vulnerable_Dependency_Management_Cheat_Sheet.html) · [CI/CD Security](https://cheatsheetseries.owasp.org/cheatsheets/CI_CD_Security_Cheat_Sheet.html)

Note:
- new in 2025, rank 3
- you install hundreds of packages you never read
- pnpm: lockfile committed, frozen lockfile in CI, pnpm audit
- who can publish? who can push to CI?
- bridge: slopsquatting (Part 4)

## [A04 – Cryptographic Failures](https://owasp.org/Top10/2025/A04_2025-Cryptographic_Failures/)

- Missing or weak crypto for data in transit and at rest
- Typical: HTTP, MD5/SHA-1 for passwords, hard-coded keys, weak randomness, secrets in repos
- Fix: TLS everywhere, strong standard algorithms, **never roll your own**, manage keys properly

**Cheat Sheets:** [Cryptographic Storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html) · [Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) · [Transport Layer Security](https://cheatsheetseries.owasp.org/cheatsheets/Transport_Layer_Security_Cheat_Sheet.html) · [Key Management](https://cheatsheetseries.owasp.org/cheatsheets/Key_Management_Cheat_Sheet.html)

Note:
- passwords: Argon2id, bcrypt – not "fast hash"
- encryption ≠ hashing ≠ encoding
- secrets in git history stay there
- Juice Shop: "Weird Crypto"

## [A05 – Injection](https://owasp.org/Top10/2025/A05_2025-Injection/)

- Untrusted data is interpreted as code or command
- Typical: SQL injection, **XSS**, OS command, NoSQL, LDAP
- Fix: **parameterized queries**, context-aware output encoding, allow-list validation

**Cheat Sheets:** [Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Injection_Prevention_Cheat_Sheet.html) · [SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html) · [Query Parameterization](https://cheatsheetseries.owasp.org/cheatsheets/Query_Parameterization_Cheat_Sheet.html) · [XSS Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html) · [OS Command Injection Defense](https://cheatsheetseries.owasp.org/cheatsheets/OS_Command_Injection_Defense_Cheat_Sheet.html)

Note:
- data vs. code – keep them apart
- ORM ≠ automatic safety (raw queries)
- frameworks encode by default – until innerHTML / v-html
- Juice Shop: login as admin (SQLi), DOM XSS
- LLM prompt injection = other list

## [A06 – Insecure Design](https://owasp.org/Top10/2025/A06_2025-Insecure_Design/)

- Flaw is in the design – perfect code can't fix it
- Typical: no threat model, missing limits on business flows, unclear trust boundaries, weak recovery flows
- Fix: threat modeling early, secure design patterns, abuse cases next to use cases

**Cheat Sheets:** [Secure Product Design](https://cheatsheetseries.owasp.org/cheatsheets/Secure_Product_Design_Cheat_Sheet.html) · [Threat Modeling](https://cheatsheetseries.owasp.org/cheatsheets/Threat_Modeling_Cheat_Sheet.html) · [Abuse Case](https://cheatsheetseries.owasp.org/cheatsheets/Abuse_Case_Cheat_Sheet.html)

Note:
- can't be found by scanners
- question: "what could go wrong?"
- what if a user does this 1000×? with someone else's ID?
- cheap in design, expensive after release

---

## [A07 – Authentication Failures](https://owasp.org/Top10/2025/A07_2025-Authentication_Failures/)

- Weak proof of identity or weak session handling
- Typical: no brute-force/credential-stuffing protection, weak or default passwords, weak recovery, sessions not invalidated
- Fix: MFA, breached-password checks, rate limiting, solid session management

**Cheat Sheets:** [Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) · [Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) · [Multifactor Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html) · [Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)

Note:
- don't build your own auth
- recovery flow = back door
- logout must invalidate server-side
- Juice Shop: admin password strength

---

## [A08 – Software or Data Integrity Failures](https://owasp.org/Top10/2025/A08_2025-Software_or_Data_Integrity_Failures/)

- Code or data is trusted without verifying integrity
- Typical: unsigned updates, insecure deserialization, scripts from untrusted CDNs, unprotected pipelines, tampered tokens
- Fix: verify signatures, Subresource Integrity, never deserialize untrusted data, protect the pipeline

**Cheat Sheets:** [Deserialization](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html) · [Third Party JavaScript Management](https://cheatsheetseries.owasp.org/cheatsheets/Third_Party_Javascript_Management_Cheat_Sheet.html) · [CI/CD Security](https://cheatsheetseries.owasp.org/cheatsheets/CI_CD_Security_Cheat_Sheet.html)

Note:
- relation to A03: A03 = what you pull in, A08 = trusting it unverified
- JWT: verify signature, fix algorithm
- Juice Shop: forged / unsigned JWT

---

## [A09 – Security Logging and Alerting Failures](https://owasp.org/Top10/2025/A09_2025-Security_Logging_and_Alerting_Failures/)

- Without logs and alerts, attacks stay unnoticed
- Typical: logins & access failures not logged, logs only local, nobody gets alerted, secrets/PII in logs, log injection
- Fix: log security events, central & tamper-resistant, **alert** + response process

**Cheat Sheets:** [Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) · [Application Logging Vocabulary](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Vocabulary_Cheat_Sheet.html)

Note:
- "alerting" = new in the name
- what do we log in our projects?
- never: passwords, tokens, full card data
- sanitize log input (log injection)

---

## [A10 – Mishandling of Exceptional Conditions](https://owasp.org/Top10/2025/A10_2025-Mishandling_of_Exceptional_Conditions/)

- Errors and unusual states handled badly or not at all
- Typical: unhandled exceptions → crash/DoS, **fail open**, stack traces leak internals, inconsistent handling
- Fix: handle at every layer, **fail closed**, generic message to the user / details to the log, test error paths

**Cheat Sheets:** [Error Handling](https://cheatsheetseries.owasp.org/cheatsheets/Error_Handling_Cheat_Sheet.html) · [Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

Note:
- new in 2025, rank 10
- happy path tested, error path not
- fail-open example: auth service down → access granted
- Juice Shop: "Error Handling" challenge

## From finding to fix

1. **Spot** the weakness
2. **Name** it – Top 10 category (later: CWE)
3. **Look up** the Cheat Sheet
4. **Fix the root cause** – and add a test

In the challenge hunt: for every finding, tell us **category** and **fix**.

Note:
- check-in format: finding – category – fix
- fundamentals stay the same, AI or not (Part 4)
- Q&A ~5 min
